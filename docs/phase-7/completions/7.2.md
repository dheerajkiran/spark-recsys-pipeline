# Checkpoint 7.2 — local platform foundation

Date: November 10, 2026. Original branch: `phase7-foundation` (based on `phase7-contracts`). Subsequently merged with checkpoint 7.1 via PR #15 as `2ed3d9a` on `main`. No AWS deployment or AWS credentials.

The new TypeScript API package has a transport-independent request handler, local HTTP server, Lambda HTTP API payload 2.0 adapter, strict local configuration, structured errors, and a public health response. Protected routes remain closed until checkpoint 7.3. The local storage and workflow modules provide durable development artifacts and basic job transitions, with the single-process limitations documented in the API README. The CPU image reuses the existing DeepFM model and training entry point with explicit work, input, and artifact paths. It does not assert that customer CSV training or AWS orchestration works yet.

Local setup: `npm ci`, `LOOP_DATA_ROOT=/tmp/loop-platform-local npm run dev`, then `curl -i http://127.0.0.1:4100/health`. Run `npm run typecheck`, `npm run lint`, `npm run build`, and `npm test`. The ranker self-check is `LOOP_WORK_ROOT=/tmp/loop-work LOOP_ARTIFACT_ROOT=/tmp/loop-artifacts .venv/bin/python -m services.ranker.main selfcheck`; the Docker equivalent is in `docker/platform/README.md`. Fresh clones can create the Python environment from the pinned requirements in the repository. No ignored fixture, checkpoint, or `.venv` path is required by the source.

The CI workflow checks TypeScript, contracts, existing frontend and Python regressions, and builds the CPU image on GitHub's runner. Local verification on November 10: TypeScript build, typecheck, lint, and four API tests passed; 101 contract tests, 143 training/serving tests, and 94 frontend tests passed. The CPU image built locally and its container self-check returned `status: ok`, `device: cpu`, and PyTorch 2.5.1. Startup without `LOOP_DATA_ROOT` returned the expected configuration error. A cloud account has not been used.
