# Local API foundation

From the repository root with Node 22, run `npm ci`, then set `LOOP_DATA_ROOT` to an absolute writable directory and run `npm run dev`. `LOOP_HOST` defaults to `127.0.0.1` and `LOOP_PORT` to `4100`. The server rejects startup with a clear message if the data root is missing or relative. `GET /health` is public. Authentication defaults to disabled, keeping protected routes closed; follow the [identity and credential guide](../../docs/phase-7/identity-and-credentials.md) to enable signed local tokens or configure Cognito verification.

The asynchronous domain function in `src/application.ts` is shared by the local Node HTTP adapter and the API Gateway HTTP API payload 2.0 Lambda adapter. Both return JSON and `X-Request-ID`. HTTP/base64 bodies are bounded at 256 KiB. The Lambda handler is an adapter factory; deployment wiring is deferred to the AWS phase, and local JWT trust is forbidden in Lambda.

`LocalStorage` persists job metadata as JSON and artifacts by SHA-256 under `LOOP_DATA_ROOT`. `LocalWorkflowRunner` exercises queued → running → succeeded/failed transitions with one active job per process. This is a single-process development implementation: it does not provide cross-process compare-and-swap, distributed leases, retries, DynamoDB consistency, or Step Functions semantics. Those must be proven before replacing it in the cloud.

Checkpoint 7.3 adds separate `LocalIdentityStore` and `DynamoIdentityStore` adapters with conditional all-or-none transactions. Project creation/list/read and key issuance/list/revocation are implemented. Keys are project-bound, scoped, expire within 30 days, disclose their secret once, and are verified against current persisted revocation state. Other project operations enforce authentication/membership/permissions and input validation before returning a gated `503`; public demo sessions are disabled. These adapters do not upgrade the old workflow runner's semantics.

Run `npm run typecheck`, `npm run lint`, `npm run build`, and `npm test`. Set `LOOP_DYNAMODB_TEST_ENDPOINT` to an explicitly local DynamoDB endpoint to include the two integration tests; CI supplies DynamoDB Local. Without it, those two tests are skipped. No AWS account is used by the test suite.
